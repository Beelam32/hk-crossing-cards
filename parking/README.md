# 香港泊車 · 實時車位（手機版）

單頁網頁，唔使裝 app。目標：**手機一秒內開得到，睇到附近邊個場有位**。

## 點解係網頁
- app 要上架、審批、叫人下載；小程序要企業認證。呢個工具嘅使用頻率係「一星期幾次、每次 30 秒」，網頁最合適。
- 加到手機主畫面（Safari 分享 → 加入主畫面）就有 app 圖示，離線都開得返上次數據。

## 數據從哪來
| 用途 | 來源 | 大小 |
|---|---|---|
| 場地靜態資料（名、地址、座標、限高、時租） | `parking/data/info.json`，由 Actions 每日 03:20 重建 | 111 KB（gzip 20 KB） |
| 實時車位 | 前端直接打 `api.data.gov.hk/v1/carpark-info-vacancy?data=vacancy` | 99 KB（每 90 秒） |

`vacancy_type` 依運輸署規格 V1.6：`A` 有數字、`B` 有位無數字、`C` 關閉。
唔好把 B/C 當「滿」——呢個坑踩過，會誤報幾百個場已滿。

## 手機順暢的三個關鍵
1. **虛擬滾動**：畫面永遠只有 13–14 行 DOM，唔理總共幾多場。
2. **地圖像素網格聚合**：zoom < 13 時把相鄰場併成一個泡泡（591 場 → 41 個），zoom ≥ 13 才逐場顯示。
3. **靜態資料 localStorage 快取**：第二次開直接由本機讀，只抓 99 KB 實時數。

## 實測（iPhone 390×844 模擬）
| 項目 | 數字 |
|---|---|
| 首行出現 | 0.10 s |
| DOM 節點（591 場） | 173 |
| 滾動 FPS | 51 |
| 地圖標記（591 場，z11） | 41 個聚合泡泡 |
| 6,000 場重新排序＋重繪 | 11 ms |
| 記憶體 | 3–8 MB |

即係：**列表 6,000 場都唔會卡**；真正嘅上限係地圖——超過約 2,000 場要再加 viewport 分頁。

## 維護
- 資料重建：`python parking/build.py`（要 `requests` 都唔使，純標準庫）
- 前端改動：直接改 `index.html`，無 build step、無 npm
- 新增欄位：改 `hkparking.py` 的 `slim()`，前端讀短欄位名（`n` 名、`d` 區、`h` 限高、`p` 時租）
